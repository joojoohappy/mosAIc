# mosAIc v0.1 release checklist

Status on 2026-10-22: **release candidate in code, not deployed or verified.** The code side is done and tested. What remains needs access to Vercel, Google AI Studio and the recipe creators.

Vercel projects: `mos-a-ic-web` (root `apps/web`) and `mos-a-ic-api` (root `apps/backend`). Merging PR #2 into `main` is expected to trigger a **production** deployment of both, so the merge is the release step.

## 1. Code (done)

- [x] Live generation through Gemini implemented, with honest fallback; tested against a fake model server only (real-key run is in step 4)
- [x] Results in Vercel Blob; live generation off on Vercel without Blob
- [x] Cost and abuse limits, unforgeable visitor identity, duplicate protection
- [x] Upload checks by content, size caps, body cap
- [x] Privacy and terms pages, consent line, 30-day result expiry
- [x] Accessibility (axe, 0 serious), phone layout, link check, performance budget
- [x] `scripts/test-all.sh` green; CI green; audits clean
- [x] Smoke test script and workflow

## 2. Owner setup (staging first: a Vercel preview of PR #2)

- [ ] **Google AI Studio:** create the API key for this project only; set a monthly spend cap (suggested ≈ $60, see [cost review](v0.1-security-cost-review.md#cost)).
- [ ] **Vercel Blob:** create a store and connect it to `mos-a-ic-api` (sets `BLOB_READ_WRITE_TOKEN`). Check current Blob pricing first.
- [ ] **`mos-a-ic-api` env vars:** `GEMINI_API_KEY`, `MOSAIC_PROXY_SECRET` (random, e.g. `openssl rand -hex 32`). Optional: `MOSAIC_DAILY_GLOBAL` and the other limits (defaults 3/min, 10/day per visitor, 50/day total, 2 concurrent).
- [ ] **`mos-a-ic-web` env vars:** `BACKEND_URL` = the API project's URL (origin only), `MOSAIC_PROXY_SECRET` = the same value as the API.
- [ ] **Function duration:** allow at least 75 s on both projects (generation can take up to 60 s).
- [ ] **Smoke test access:** in `mos-a-ic-web` enable "Protection Bypass for Automation" and add its value as the GitHub repository secret `VERCEL_AUTOMATION_BYPASS_SECRET`. (Or run the smoke test by hand from a logged-in machine.)
- [ ] **Privacy contact:** decide on a private contact for deletion requests (today `/privacy` points to GitHub Issues).

## 3. Content and rights (owner)

- [ ] Confirm each recipe's creator and Instagram link from the original post.
- [ ] Confirm the basis for showing and running each prompt (ask the creator if needed). No license is assumed.
- [ ] Fill `creatorName`, `creatorInstagramUrl`, optional `previewImageUrl` in `apps/backend/data/recipes.json`; set `tryReady: true` only for confirmed recipes.
- [ ] Legal review of `/privacy` and `/terms`.
- [ ] Decide the project license (none is set; nothing has been added).

## 4. Staging verification

- [ ] `bash scripts/smoke.sh <preview-url>` (with `VERCEL_BYPASS` if protected): all read-only checks pass and health says `live generation is on`.
- [ ] `SMOKE_GENERATE=1 bash scripts/smoke.sh <preview-url>`: one real generation reports `mode=live` and the result image loads. (Costs ≈ $0.04.)
- [ ] Open the result link in a private window and on a phone: image, source note and creator links are right.
- [ ] From two different networks, hit the per-visitor limit: each gets its own count.
- [ ] Check the API logs: one line per generation, no image data, no key, no IP.

## 5. Release (needs explicit approval)

- [ ] Approve merging PR #2 into `main` (production deployment of both projects).
- [ ] Run the smoke test against the production URL, then one `SMOKE_GENERATE=1` run.
- [ ] Record the demo video and add it to the README.

## Rollback

- Vercel: **Instant Rollback** to the previous production deployment of each project (dashboard → Deployments). The current production deployments are from `c76a78a`.
- Turn off paid generation without a redeploy: remove `GEMINI_API_KEY` (or set `MOSAIC_DAILY_GLOBAL=0`) on `mos-a-ic-api` and redeploy the existing build; the site keeps working with labelled examples.
- Code: `git revert` the merge commit of PR #2.
