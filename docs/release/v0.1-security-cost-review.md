# mosAIc v0.1 security, privacy and cost review

Reviewed 2026-10-22 against the release candidate (PR #2). Each control lists where it lives and how it is tested. Two rounds of independent review found two issues (spoofable visitor IP, paid calls without shared storage on Vercel); both are fixed and covered by tests.

## Security controls

| Requirement from the brief                                   | Control                                                                                                                                                                                                                    | Evidence                                                                                    |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| AI credentials never in browser code                         | `GEMINI_API_KEY` is read only by the backend (`apps/backend/app/generation.py`). The website has no AI SDK and no `NEXT_PUBLIC_*` secrets; it only proxies `/api/*`.                                                       | `grep` of `apps/web` and `packages/` finds no key; build output contains none               |
| Secrets never committed                                      | `.env` files and `OWNER-NOTES.md` are gitignored; `.env.example` files contain empty values only. Docker image does not copy `.env`.                                                                                       | `.gitignore`, `apps/backend/.dockerignore`                                                  |
| File type from actual content                                | Magic bytes, then a full Pillow decode; 40-megapixel cap against decompression bombs. File name and declared MIME type are ignored.                                                                                        | `UploadValidation`, `test_api.sh` "text renamed .jpg", "broken jpeg"                        |
| Upload size limit                                            | 8 MB per photo (413); 8.5 MB per request body, enforced before multipart parsing, including chunked bodies.                                                                                                                | `test_oversized_upload_is_413`, `test_body_cap_rejects_before_parsing`                      |
| Abusive API requests                                         | Per-visitor rate and daily limits, global daily budget, concurrency gate, duplicate detection. Visitor identity cannot be forged with `X-Forwarded-For`; uvicorn runs with `--no-proxy-headers`.                           | `test_limits.py`, `tests/proxy.test.mjs`                                                    |
| Safe CORS                                                    | No CORS headers at all. Browsers reach the API only through the website's own origin, so other sites cannot call it from a visitor's browser.                                                                              | `apps/backend/app/main.py` (no CORS middleware)                                             |
| Hidden recipe prompts                                        | Only `promptVisibility: public` prompts are returned. The client never sends prompt text; the server looks it up by `recipeId`. No copy of `recipes.json` in the web bundle. Results and logs carry no prompt.             | `test_hidden_or_unknown_visibility_never_leaks_the_prompt`                                  |
| No sensitive logging                                         | Logs record recipe id, mode, reason code and duration. Never image bytes, prompt text, keys or visitor IPs. Provider error text is truncated to 300 characters and never returned to clients.                              | `test_provider_failure_detail_stays_in_the_log`; `mosaic.api` / `mosaic.generation` loggers |
| Dependency vulnerabilities                                   | `pnpm audit` and `pip-audit` clean; Next.js 16.3.8; `sharp` and `source-map-js` pinned through overrides; Python direct dependencies pinned. Both audits run in CI.                                                        | CI                                                                                          |
| Upload and output storage access                             | Uploads are never stored. Results are stored `private` in Vercel Blob (or local disk) and served only through `/static/results/<32-hex>.<ext>`; Blob URLs never reach browsers. Only `storage/seed/` is served statically. | `test_fallback_sidecars_are_not_served`, `test_storage.py`                                  |
| No user-controlled URLs or paths reaching internal resources | Result ids and file names must match strict regexes before touching storage. The model endpoint is fixed in code. Recipe image URLs come from the reviewed data file, not from users. API docs endpoints are disabled.     | `test_api.sh` "path traversal", "bad result id"; smoke "API docs are not exposed"           |
| Visitor IP trust between website and API                     | `apps/web/proxy.ts` strips client-sent `x-mosaic-*` headers and signs the platform IP with `MOSAIC_PROXY_SECRET`; the API compares it in constant time.                                                                    | `test_client_ip_from_website_needs_the_secret`, `tests/proxy.test.mjs`                      |

## Privacy

- **Uploads:** forwarded to Google's Gemini API for the one generation and not written to disk or Blob. Google's handling is governed by the [Gemini API terms](https://ai.google.dev/gemini-api/terms), linked from `/privacy`.
- **Results:** private by default. Reachable only through an unguessable 128-bit id; nothing lists them. Sharing is an explicit action on the result page (copy link / native share).
- **Retention:** results older than `MOSAIC_RESULT_RETENTION_DAYS` (default 30) are no longer served. They are **not yet deleted** from storage automatically; scheduled deletion is on the v0.2 backlog. `/privacy` says this.
- **On the device:** favorites are kept in the browser's local storage only.
- **No accounts, no tracking, no analytics, no cookies** in v0.1.
- **Third-party recipes:** the three seed prompts come from public Threads posts. Creators and usage rights are unverified, so they are shown as `來源待確認` and not open for Try. No license or permission has been assumed.
- `/privacy` and `/terms` are written in plain language and **need a legal review** before a public launch.

## Remaining risks

| Risk                                                                                  | Severity           | Mitigation now                                       | Follow-up                                             |
| ------------------------------------------------------------------------------------- | ------------------ | ---------------------------------------------------- | ----------------------------------------------------- |
| Real Gemini API differs from the documented request/response                          | High               | Honest fallback; no crash, no fake "live" result     | One real generation on staging before launch          |
| Global budget is read-then-write, not atomic; can overshoot by a few calls under load | Medium             | Concurrency gate; small default budget               | Provider spend cap (required); atomic counter in v0.2 |
| Per-visitor counters are per instance                                                 | Low                | Global budget is shared; default limits are small    | Shared store in v0.2                                  |
| Without `MOSAIC_PROXY_SECRET` on Vercel, visitors may share one limit bucket          | Low (fails closed) | Stricter, never looser                               | Set the secret on both projects                       |
| Expired results remain in storage                                                     | Low                | Not served after 30 days                             | Scheduled deletion in v0.2                            |
| Generated images could be misused (e.g. a photo of someone else)                      | Medium             | Terms prohibit it; Gemini's own safety filters apply | Report button / moderation in a later version         |
| Unverified third-party prompts                                                        | Medium             | Not open for Try; source always linked               | Owner verifies each creator                           |

## Cost

### Prices used (checked 2026-10-22)

From Google's [Gemini API pricing](https://ai.google.dev/gemini-api/docs/pricing) for `gemini-nano-banana-2.1`, paid tier, standard:

- Image output: $30 per 1M tokens; a 1K image (the default, used by mosAIc) is 1,120 tokens = **$0.0336 per image**.
- Input: $1.50 per 1M tokens. The page does not give the token count of an input image; at a few hundred to ~1,100 tokens for the photo plus ~400 for the prompt, input is roughly **$0.001–0.002** per request (estimate).
- No free tier for this model.

**Estimated cost per live generation: about $0.035–0.036.** Failed calls are counted against the daily budget and may be billed.

### Monthly estimate with the default limits

| Scenario                                          | Paid calls / day | Model cost / month (30 days) |
| ------------------------------------------------- | ---------------- | ---------------------------- |
| Quiet launch                                      | 5                | ≈ $5.4                       |
| Busy day every day                                | 20               | ≈ $21.6                      |
| Hard ceiling (`MOSAIC_DAILY_GLOBAL=50` every day) | 50               | **≈ $54**                    |

The ceiling is the maximum the app will spend under normal operation. The non-atomic counter can let a few extra calls through under parallel load, which is why a provider-side cap is required.

**Hosting assumptions:** both Vercel projects are on the Hobby plan, which Vercel limits to non-commercial use; a paid launch or a sale would need Pro. Vercel Blob stores each result image (~1–2 MB as a 1K PNG); at the ceiling, about 1,500 images (2–3 GB) accumulate per month until scheduled deletion exists. Check Vercel's current Blob pricing before enabling it; it has not been activated.

### Spending cap (required before launch)

Google AI Studio supports a monthly project spend cap (AI Studio → Spend → Monthly spend cap; Google marks it experimental) and enforces billing-account tier caps (Tier 1: $250/month). Google notes billing can lag about 10 minutes, so the cap is a backstop, not a precise limit. Recommended: set the project cap to about $60/month, just above the in-app ceiling. Alternatively use a prepaid balance, which stops all keys when it reaches $0.

No paid service has been activated and no money has been spent in this work.
