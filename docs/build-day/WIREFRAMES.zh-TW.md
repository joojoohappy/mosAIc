# 畫面資訊架構參考

> **待檢視：**本文件翻譯自較早版本的 [WIREFRAMES.md](WIREFRAMES.md)。其中的權限介面、隱藏 prompt、creative context 與分享功能屬於早期構想；實作前應依目前的 [PROJECT.md](PROJECT.md) 和 [CREATIVE-RECIPE.md](CREATIVE-RECIPE.md) 決定取捨。

**參考圖，不是規格。** 以下只描述各畫面可能需要的資訊、操作與狀態，不規定視覺設計。Fable5 示範後，團隊可以調整畫面、順序及互動方式。**Current hypotheses are not requirements.**

暫定流程：`Gallery → Recipe → Create → Result`。它可以是四個頁面、幾個面板，或更精簡的互動。實際流程與路徑以 [BUILD-DAY.zh-TW.md](BUILD-DAY.zh-TW.md) 的現場決定為準；共用 recipe ID 見 CREATIVE-RECIPE.md。

## Gallery｜探索

使用者要理解：「有哪些作品值得試？」

```text
[專案名稱]             [簡短介紹]

[作品預覽]             [作品預覽]
 標題                   標題
 原作者                 原作者
 [查看 recipe]          [查看 recipe]

[其他已備妥的項目]
```

資訊順序：預覽圖 → 標題 → 原作者 → 查看 recipe。卡片使用共用 recipe ID。搜尋、篩選、無限捲動與收藏均非必要項目。

應考慮的狀態：有可用項目、沒有可用項目、缺少預覽圖。缺圖時保留可閱讀的文字與原始貼文連結。鍵盤操作與窄螢幕閱讀順序應清楚。

檢查問題：使用者是否能選出一份 recipe，同時注意到分享它的創作者？

## Recipe｜了解來源

使用者要理解：「這是誰分享的？可以如何嘗試？」

```text
[返回 Gallery]
[原作者提供的作品預覽，若可展示]
標題／簡介
原作者       [前往已核對的 IG] [查看原始貼文]

Prompt／使用說明
[公開的 prompt 原文]

[使用自己的照片試試] 或 [尚無法試用的原因]

—— 以下為早期構想，是否加入由團隊決定 ——
[Prompt 不公開時的說明]
[使用權限摘要]
[Creative context]
```

創作者身分與原始貼文應容易找到。IG 未核對時不顯示 IG 入口。早期草稿提出公開／隱藏 prompt、Try／Remix／Share／商用／AI training 權限及 creative context；目前三份 seed 均為使用者提供的公開 prompt，這些額外介面不是當前必做範圍。

應考慮的狀態：內容齊全、IG 未核對、預覽圖缺少、暫時無法試用、recipe ID 不存在。對缺失資料給出明確說明，不建立虛構連結。

檢查問題：使用者是否知道 prompt 的來源，以及下一步能做什麼？

## Create｜平台內試用

使用者要理解：「要上傳什麼？按下按鈕後會發生什麼？」

```text
[返回 Recipe]
正在使用 [Recipe 標題]／來源 [原作者]
[即時生成或示範模式說明]

[選擇照片] → [預覽] [更換]
[實際支援格式與大小限制]
[必要的圖片處理說明]

[開始生成] 或 [查看預備示範結果]
[等待／錯誤／重試或備案]
```

按鈕文字須與實際行為一致。「查看示範結果」不能呈現為已從本次上傳照片生成。送至外部生成服務前，應依實際整合方式說明圖片會如何處理；不宣稱尚未核實的保存或刪除政策。活動測試可先使用團隊準備的照片。

應考慮的狀態：尚未選圖、已選圖、格式或大小不符、生成中、超時或失敗、提供示範結果。返回 Recipe 時，盡可能保留所選 recipe。

檢查問題：使用者是否知道這次使用哪張照片與哪份 prompt，失敗時是否知道下一步？

## Result｜結果

使用者要理解：「生成了什麼？原 prompt 來自哪裡？」

```text
[結果圖片] 或 [結果無法顯示]
[即時生成／事先生成／示意的說明]

使用的 Recipe：[標題]
Prompt 來源：[原始貼文]
原作者：[已核對的名稱／連結]

[再次嘗試] [返回 Recipe]
[若團隊決定且適用，才提供分享或匯出]
```

即時生成的結果可以說明使用者提供了輸入照片。事先生成或示意結果應標明對應的預備素材；若結果與本次上傳照片無關，不可使用「由你的照片生成」等敘述。

應考慮的狀態：即時生成、事先生成、示意、結果無法取得、結果 ID 無效或重新整理後失效。若結果不見，不應暗中換成另一張圖並宣稱是同一結果。

檢查問題：觀看者是否分得清結果的來源、原 prompt 的創作者與實際完成的功能？

## 共通原則

- 每個狀態有一個清楚的下一步；尚未完成的功能不顯示為可用。
- 原作者與原始貼文連結在探索、試用和結果中保持一致。
- 錯誤訊息使用清楚文字，並提供可執行的下一步。
- 控制項應有標籤、可用鍵盤操作，且在展示用的窄螢幕上仍可閱讀。
- 本文件不決定最終視覺樣式。
