MOSAIC 前端對接

兩個 endpoint，一個型別檔，四個步驟。後端是 Python / FastAPI，但你不需要知道 — 打 /api/* 就好。

2 endpoints 無 CORS 無需輪詢 後端 :8000
1

一次性設定

加到 mosaic/next.config.js（已經幫你寫好了，確認在就好）。瀏覽器只跟 :3000 講話，所以沒有 CORS 問題。

async rewrites() {
  return [
    { source: '/api/:path*',    destination: 'http://localhost:8000/api/:path*' },
    { source: '/static/:path*', destination: 'http://localhost:8000/static/:path*' },
  ];
}

不要在 app/api/ 底下放任何 route.ts。Next 的 rewrites 是 afterFiles，實體檔案會優先，請求就到不了後端了。

2

型別（已在 repo 裡）

mosaic/types/generation.ts 和 types/recipe.ts，直接 import。

// types/generation.ts
export type ResultMode = 'live' | 'cached' | 'mock';

export type GenerationResult = {
  resultId:   string;
  recipeId:   string;
  mode:       ResultMode;      // 一定有值
  sourceNote: string;          // 原樣顯示，不要改寫
  imageUrl:   string | null;   // mode==='mock' 時為 null
  fallbackReason: string | null; // 除錯用，不要顯示給使用者
  recipeTitle:         string;
  creatorName:         string | null;  // 未核實 → null
  sourcePostUrl:       string;
  creatorInstagramUrl: string | null;  // 未核實 → null
  createdAt:  string;          // ISO 8601 UTC
};

Recipe 資料讀 data/recipes.json（3 筆：seed-01/02/03）。只在 server component 讀 — 裡面有 prompt 原文，不要進 client bundle。

3

送出與取回

POST /api/generate 是同步的，會卡住最多 60 秒。不需要輪詢 — 但 loading state 一定要做，而且不要設短 timeout。

// 送圖 → 拿 resultId（這一步會等很久）
export async function generate(recipeId: string, file: File) {
  const body = new FormData();
  body.append('recipeId', recipeId);
  body.append('image', file);

  const res  = await fetch('/api/generate', { method: 'POST', body });
  const json = await res.json();
  if (!res.ok) throw new Error(json.error);   // 見步驟 5
  return json.resultId as string;             // 32 個 hex 字元
}

// 用 resultId 取結果（重新整理後仍然讀得到）
export async function getResult(resultId: string) {
  const res = await fetch(`/api/results/${resultId}`);
  if (!res.ok) throw new Error('unknown_result');
  return res.json() as Promise<GenerationResult>;
}

限制：jpeg / png / webp，8MB 以內。後端用 magic bytes 驗證，改副檔名沒有用。

4

依 mode 決定畫面

後端會告訴你這張圖是怎麼來的。三種都要能畫 — 目前測試環境全部回 mock。

live 正常顯示圖片 真的由使用者這次的照片生成。imageUrl 有值。
cached 顯示圖片 ＋ 明顯的揭露文字 是預備素材，不是使用者的照片生成的。imageUrl 有值，但畫面絕不能寫「你的照片生成完成」。
mock 沒有圖片，版面要撐得住 imageUrl === null。顯示佈局和 sourceNote，不要出現破圖。 
{result.imageUrl
  ? <img src={result.imageUrl} alt={result.recipeTitle} />
  : <EmptyResult />}

{/* 三種 mode 都要顯示，原文照登 */}
<p className="disclosure">{result.sourceNote}</p>

{/* 創作者未核實時，只放原貼文連結 */}
{result.creatorName
  ? <a href={result.creatorInstagramUrl ?? result.sourcePostUrl}>{result.creatorName}</a>
  : <a href={result.sourcePostUrl}>來源待確認 · 查看原始貼文</a>}
5

錯誤

失敗一律是 { "error": "..." }。這六個是全部，不會有別的。

HTTPerror畫面要說什麼
400missing_recipe_id前端 bug，不該發生
400missing_image請先選一張照片
400unsupported_type只支援 JPEG / PNG / WebP
400too_large照片請小於 8MB
404unknown_recipe找不到這份 recipe
404unknown_result結果不存在或連結已失效

GET /api/health → { "ok": true }。打不到就是後端沒開，顯示「後端未啟動」，不要顯示一般錯誤 — 這會省掉你半小時的除錯。

三件事不能做

  1. 不要自己寫結果的說明文字。sourceNote 原樣顯示。那句話是伺服器產生的，決定了畫面有沒有謊報「這是你的照片生成的」。
  2. 不要傳 prompt。只傳 recipeId，後端自己去查。傳 prompt 等於讓任何人打開 devtools 就能免費用我們的 API key。
  3. 不要把 creatorName 的 null 填成任何名字。三份 seed 的作者都還沒核實。null 就顯示「來源待確認」＋原貼文連結。

怎麼跑起來

# repo 根目錄，一次起前後端
./dev.sh

# 只想確認後端活著
curl localhost:3000/api/health          # 走 proxy

# 不等前端，先看一筆真實 payload 長什麼樣
curl -F recipeId=seed-01 -F image=@photo.jpg localhost:3000/api/generate

後端還沒接生成服務，所以現在每一筆都是 mock（imageUrl: null）。這正好是你最該先做對的狀態 — 先把 mock 畫好，live 和 cached 只是多一張圖。
